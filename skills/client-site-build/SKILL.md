# Сайт для локального бизнеса без пропущенных метрик

Сайт делаем так, чтобы при сдаче сканер `maps-seo-scanner` не нашёл провалов: это и есть
объективное «до/после» для клиента. Метрики, пороги и юрисдикции — каталог
`docs/METRICS.md` репозитория сканера; здесь — порядок работы.

- `CHECKLIST.md` — **все 214 метрик в порядке работы над сайтом** (бриф → стек → структура →
  `<head>` → контент → JSON-LD → боты → скорость → мобайл → право → безопасность → заявки →
  проверка → после запуска). Прочитай целиком до начала работы и иди по разделам.
- `TEMPLATES.md` — заготовки: `<head>`, robots.txt с ИИ-ботами, JSON-LD LocalBusiness + услуги +
  крошки, заголовки безопасности (nginx, `_headers`), скрипт проверки вёрстки, поиск заглушек,
  проверка ботов.

Оба файла — ссылки на `docs/site-build/` репозитория сканера; правки вносить туда (тест
сканера проверяет, что чеклист покрывает каждый id каталога).

## Порядок

1. **Бриф** (раздел 0 чеклиста). Факты — только из карточек на картах и документов клиента:
   NAP, часы, услуги с ценами, реквизиты и лицензии по стране, ссылки на карточки. Если клиент из
   сканера — данные компании есть в интерфейсе сканера (страница компании) и в API
   `GET http://127.0.0.1:8787/api/businesses/{id}`, если сервер запущен. Чего не хватает —
   спросить у пользователя; не выдумывать адрес, цены, отзывы, лицензии.
2. **Страна** определяет право (политика ПДн, согласие, cookie, выходные данные: ИНН/ОГРН,
   Impressum, mentions légales…), язык и формат адреса — раздел 9 чеклиста.
3. **Стек:** весь текст в исходном HTML (статическая сборка или SSR), не SPA — иначе ИИ-боты
   увидят пустую страницу (I06, частый провал).
4. **Вёрстка и контент** по разделам 2–11 чеклиста; шаблоны — из `TEMPLATES.md`.
5. **Проверка** (раздел 12) — обязательна, сдавать без неё нельзя:

   ```sh
   maps-seo-scanner audit http://localhost:{порт}/ \
     --country ru --city "Москва" --service "стоматология" \
     --name "{название как в картах}" --phone "+7…" --address "{адрес как в картах}" \
     --hours "Mo-Fr 09:00-21:00; Sa 10:00-18:00"
   ```

   Нет бинарника — поставить из релиза (README сканера) или собрать: `scripts/build.sh` в репозитории. Флаги `--json` (для разбора)
   и `--all` (показать пройденные). Код выхода: 0 — критичных нет, 1 — есть, 2 — сайт не открылся.
   Исправить всё в «Критично» и «Внимание»; оставшееся «Внимание» — только с причиной в отчёте
   пользователю. Раздел «Не измерено» пройти вручную по чеклисту: вёрстку (E02–E04, E06, E07, Q02)
   — скриптом из `TEMPLATES.md` на 360 и 1366 px, Lighthouse — Performance, Accessibility, Best
   Practices, SEO ≥ 90 на мобайле.
6. **После выкладки** — тот же `audit` на боевом домене (домен, TLS, редиректы, HSTS, SPF/DMARC,
   с ключом PageSpeed в настройках сканера — Core Web Vitals) и проверка ботов из `TEMPLATES.md`.
7. **Вне кода** (раздел 13): ссылка на сайт с UTM в карточках, один NAP на всех картах,
   подтверждение в Search Console, Вебмастере и Bing, отправка sitemap. Сделать то, что можно,
   остальное — списком пользователю.

## Правила

- Ничего не скрывать от сканера: никаких особых версий страниц для ботов (клоакинг), скрытого
  текста, самоназначенных звёзд рейтинга в разметке, купленных ссылок.
- Тестовые заявки — только на локальной копии; на рабочем сайте клиента формы не отправлять.
- Обучающих ИИ-ботов блокировать или нет — решает клиент; поисковых не блокировать.
- Правовые тексты — по шаблону страны, но с пометкой пользователю «сверить с юристом».
- В итоговом сообщении: вывод `audit` (балл, сколько критичных/внимание), что проверено вручную,
  что осталось после выкладки и вне кода.
