# Каталог метрик сканера карт: SEO, ИИ-поиск, лендинг

Версия от 24.11.2026 (добавлен раздел R — факторы Яндекса; раздел J «Видимость в ответах ИИ» убран,
раздел I дополнен по исследованию факторов ИИ-ответов). Пороги стартовые, их нужно калибровать по реальной выборке.
Источник правды — этот файл; `metrics.yaml` генерируется из него скриптом
`scripts/gen_metrics_yaml.py` (см. «Как обновлять»).

## Зачем

Сканер Google / Яндекс / Apple Карт находит компании без сайта или с плохим лендингом. Им предлагаем
SEO, оптимизацию под ИИ-поиск (чтобы ассистенты рекомендовали именно их) и доработку лендинга.
Для продажи и для отчёта «до/после» нужны объективные, воспроизводимые показатели: что меряем,
чем, где порог.

**Обозначения в колонке «Где»:**

- **В** — внешний скан, доступ не нужен. Годится для поиска лидов.
- **Д** — нужен доступ клиента (GSC, Вебмастер, Метрика, кабинеты карт). Для отчёта после работ.
- **Д (В≈)** — точно с доступом, грубо без него.

Где порог относительный, сравниваем с **медианой 10 конкурентов в радиусе или нише**.

## Что честно обещать по «ИИ-оптимизации»

- **Google AI Overviews / AI Mode** работают на том же индексе и ранжировании, что и обычный поиск.
  Особой разметки нет, llms.txt Google игнорирует (Search Central «AI features and your website»,
  гайд от 15.05.2026, уточнение от 15.06.2026; сведения по пересказам, первоисточник перепроверить).
  Значит, для Google «ИИ-оптимизация» — это обычное SEO плюс разрешённый сниппет.
- **ChatGPT, Perplexity, Claude, Алиса/Нейро, Copilot** зависят от трёх вещей: пускают ли ботов,
  виден ли контент без JS, есть ли сайт в индексе Bing/Яндекса. Плюс присутствие на площадках,
  которые они цитируют (карты, агрегаторы, отзовики), и согласованность фактов о компании.
- **Приложение Gemini** берёт источники через Google-Extended: запрет этого токена в robots.txt убирает
  сайт и из обучения, и из ответов Gemini (на AI Overviews и AI Mode не влияет).
- **Упоминания в ответах ИИ сканер не считает.** Бесплатного и разрешённого способа нет: платные API
  ассистентов стоят денег, а бесплатный поиск в Gemini API по условиям Google нельзя хранить и
  анализировать. Ответы ИИ к тому же случайны. Поэтому сканер проверяет всё, от чего зависит
  попадание в ответ (раздел I и связанные B07, B09, C11, C21, F02, G, H02, H03), а «ИИ рекомендует
  только вас» не обещаем.

## R. Яндекс: коммерческие и региональные факторы, фильтры

## Геосетка карт (A20, SoLV)

Сетка 7×7 точек вокруг адреса с шагом 0,5–1 км (зависит от плотности города), 3–5 ключевых
запросов. В каждой точке снимается позиция в выдаче карт (SERP API с координатами).
**SoLV** = точек с позицией ≤ 3 / всех точек. Замеры «до» и «после» — на той же сетке и тех же
запросах.

## Скоринг

- Каждая проверка (`kind: check`) получает `pass / warn / fail` = 100 / 50 / 0.
  Метрики `kpi` (значение во времени) и `info` в балл не входят.
- Балл категории = Σ(вес × балл) / Σ(вес) по измеренным метрикам; неприменимые (N/A) пропускаются.
- Общий балл = взвешенное среднее категорий. Стартовые веса категорий: A 20, C 12, D 10, I 10, F 8,
  R 8, B 6, K 6, N 6, E 5, H 5, G 4, L 3, M 3, O 2, P 2, Q 2 (нормируются).
- **Стоп-факторы** перекрывают балл: A21, B01, B13, C02, C10, E01, I01, I05.

## Отбор лидов

- **Горячий лид:** нет сайта (A03), сайт мёртв или заглушка (B01, F14), вместо сайта соцсеть или
  таплинк (A04). Причём **бизнес живой**: отзывов не меньше медианы (A06), есть свежие (A07).
  Лучший лид — «много отзывов, плохой сайт».
- **Тёплый:** сайт есть, общий балл < 50, карты хуже конкурентов (A20) или сайт заброшен (F13).
- **Сигналы платёжеспособности:** пиксели рекламы (P05), онлайн-запись (N04), несколько филиалов.
- **Исключать:** закрытые; сети с высоким баллом (у них свой маркетинг).

## Этапы сканирования (поле `stage` в YAML)

- **lead** — дешёвые внешние проверки для массового поиска лидов: данные карт, сайт, robots,
  sitemap, PSI, разметка, ИИ-боты, лендинг.
- **audit** — внешние, но дорогие: геосетка (A20), SERP API (K), ссылки (L),
  каталоги (H06–H07), уникальность (F09), аффилиаты (R20). Запускаются для отобранных лидов.
- **report** — с доступом клиента, для отчёта «до/после».

## Ядро отчёта «до/после» (≈ 30 KPI)

- **Карты:** A06, A08, A18, **A20 (SoLV)**, A22, A23.
- **Техника:** C02 и C10 (pass), C07, C17, C18, D01–D03, D05.
- **ИИ:** I02, I05, I06 (pass), I08, I16, I18, I19, I20.
- **Поиск:** **K01, K02**, K03, K07; Яндекс — C19 (ИКС), **R17**, R19.
- **Ссылки:** L01.
- **Бизнес:** **N09, N10**.

## Откуда данные карт и риски

- **Google:** Places API (New) отдаёт websiteUri, rating, userRatingCount, часы, businessStatus,
  фото, до 5 отзывов. Условия ограничивают хранение: проверить перед проектированием БД.
- **Яндекс:** API Поиска по организациям (платный; условия хранения и использования проверить).
  Данные Яндекс Бизнеса доступны только по своим карточкам.
- **Apple:** официальный Maps Server API, по-видимому, не отдаёт сайт и рейтинг (не подтверждено);
  есть сторонние SERP API (SerpApi и др.). Проверить на developer.apple.com.
- Парсинг интерфейсов карт нарушает их условия (бан, юридический риск).
- **Холодный контакт:** 38-ФЗ ст. 18 — реклама по телефону или email только с согласия получателя;
  у ИП контакты — это ПДн (152-ФЗ). Формат первого касания обсудить с юристом.
- Свою нейросеть ни одна метрика не требует: всё детерминировано. Где удобно — npud
  (OCR для I07, эмбеддинги для дублей C14 / F09), правило «только NPU» соблюдается.

## Как обновлять

1. Править таблицы в этом файле: колонки и формат ID (`A01`) не менять.
2. Веса, числовые пороги, стоп-факторы и прочие машинные поля — в словарях
   `scripts/gen_metrics_yaml.py`.
3. Пересобрать YAML: `python -I scripts/gen_metrics_yaml.py`. Скрипт проверяет уникальность ID
   и что все ID из словарей есть в каталоге.
