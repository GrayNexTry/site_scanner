# Работа менеджера с лидами: ТЗ (24–25.11.2026)

Цель — чтобы менеджер вёл клиента от находки в скане до оплаты, не выходя из сканера:
видел все контакты, писал первое сообщение в один клик, вёл журнал касаний и следующий шаг,
собирал план работ с ценой и отдавал клиенту коммерческое предложение (КП) и отчёт в PDF.

Общие правила проекта: комментарии и тексты интерфейса — по-русски; логика — в `crates/core`
с тестами; сервер (`crates/server`) — тонкий слой над ядром; без новых зависимостей, если можно
обойтись; `cargo test --workspace`, `cargo clippy --workspace --all-targets` и `cd web && npm run build`
должны проходить. Не коммитить. Сервер перезапускать только если не идёт скан
(`curl -s 127.0.0.1:8787/api/scans` — нет `"status":"running"`):
`packaging/launcher/maps-seo-scanner-launch stop && …-launch start` (бинарь — `target/release/maps-seo-scanner`,
UI встраивается при `cargo build --release -p scanner-server` после `cd web && npm run build`).
Не запускать пересканирование сетей/сканов — только локальные проверки и `audit <url>` по одному сайту.
Предпочтение пользователя: «видеть всё» — данные не прятать по умолчанию, фильтры только опцией.

## 1. Данные

### Колонки `businesses` (миграция через `ADDED_COLUMNS` в `crates/server/src/db.rs`)
| колонка | тип | смысл |
|---|---|---|
| `deal_price` | REAL | цена, которую назначил менеджер (итог КП) |
| `deal_currency` | TEXT | валюта (`BYN`, `RUB`, `USD`, `EUR`, `GBP`, `PLN`…); пусто — валюта из настроек |
| `next_action_at` | TEXT | дата следующего шага `YYYY-MM-DD` |
| `next_action` | TEXT | что сделать («написать повторно в Instagram») |
| `contact_person` | TEXT | ЛПР: имя, должность |
| `extra_contacts` | TEXT (JSON) | контакты, добавленные вручную: `[{kind, value, note?}]` |
| `proposal` | TEXT (JSON) | сохранённые правки КП (см. §3) |

Статусы лида (`LEAD_STATUSES`): `new`, `contacted` (написали), `talking` (переговоры),
`proposal` (КП отправлено — **новый**), `client` (клиент), `rejected` (отказ), `skip` (не работаем).

### Таблица `activities` — журнал касаний
`id INTEGER PK, business_id INTEGER NOT NULL REFERENCES businesses(id) ON DELETE CASCADE,
at TEXT NOT NULL (RFC3339), kind TEXT NOT NULL, channel TEXT, text TEXT`, индекс по `business_id`.
`kind`: `note` (заметка), `message` (написали), `reply` (ответили), `call` (звонок), `meeting`
(встреча), `proposal` (отправили КП), `status` (смена статуса — пишется сервером сам),
`price` (смена цены — сам). `channel`: `instagram`, `email`, `phone`, `telegram`, `whatsapp`,
`viber`, `vk`, `facebook`, `visit`, `other`.

## 2. Контакты компании (ядро)

`crates/core/src/sales.rs`, `pub fn site_contacts(snap: &SiteSnapshot) -> Contacts` — со всех
обойдённых страниц: почты (`mailto:` и в тексте; без `x@2x.png`, `example.com`, `sentry`, `wixpress`,
адресов картинок), телефоны (`tel:` и `phones_in_text`, без дублей по `phone_key`, в том виде, как на
сайте), соцсети и мессенджеры (ссылки, которые `classify_website` считает Social/Messenger/LinkInBio;
вид — по хосту: instagram, telegram, whatsapp, viber, vk, facebook, tiktok, youtube, ok, linkedin, x,
taplink…). Сохранять в сводку сайта: `SiteSnapshot::summary()` → `"contacts": {...}`.

Сервер собирает список для карточки лида: `contacts: [{kind, value, url?, source, note?}]`, где
`source` — `card` (телефон, почта, ссылки из карточек `data.sources[]` — у Overture есть email и links),
`site` (из сводки сайта), `manual` (`extra_contacts`). Без дублей (телефоны — по `phone_key`, почты —
без регистра, ссылки — по хосту+пути). `url` — готовая ссылка: `tel:`, `mailto:`, `https://wa.me/<цифры>`,
`viber://chat?number=%2B<цифры>`, `https://t.me/<ник>`, сама ссылка соцсети.

## 3. План работ и КП (ядро)

`sales.rs`: пакеты работ. Каждый — `id`, название, что входит, какие метрики закрывает, цена по
умолчанию. Метрики → пакет:

| id | название | метрики |
|---|---|---|
| `new_site` | Новый сайт: одностраничник с записью и SEO под «услуга + город» | состояния мини-отчёта none, social, dead, stub |
| `maps` | Карточки на картах и контакты | A*, H02, H03, R01 |
| `https` | HTTPS и перенаправление | B04, B05, O02 |
| `speed` | Скорость загрузки | B07–B11, D* |
| `mobile` | Мобильная версия | E* |
| `indexing` | Индексация в Google и Яндексе | B06, B12, C* |
| `content` | Тексты и заголовки под «услуга + город» | F* |
| `schema` | Разметка для поисковиков и ИИ | G* |
| `ai` | Готовность к ИИ-поиску (ChatGPT, Алиса, Perplexity) | I* |
| `legal` | Документы и право: политика ПД, cookie, реквизиты | M* |
| `conversion` | Заявки: кнопки, формы, онлайн-запись, отзывы | N*, H01 |
| `security` | Безопасность | O01, O03–O06, B13 |
| `analytics` | Аналитика и цели | P* |
| `a11y` | Доступность | Q* |
| `yandex` | Факторы Яндекса | R02–R16 |

`pub fn build_proposal(results, mini_state, price_list, saved) -> Proposal`:
у пакета список пунктов — проваленные (fail) и «внимание» (warn) метрики простыми словами
(`mini::label`, иначе название метрики из каталога); пакет включён по умолчанию, если есть хотя бы
один fail; для состояний без сайта (none/social/dead/stub) — только `new_site` и `maps`;
для `hidden` (сайт есть, но не в карточке) — `maps` + обычные пакеты по сайту.
`saved` (колонка `proposal`) — правки менеджера: `{packages: [{id, enabled, price?, title?}], extra:
[{title, price}], discount?: number, note?: string, valid_days?: number}`. Итог = сумма включённых
пакетов и дополнительных строк − скидка. Прайс (`price_list`) — из настроек, по умолчанию — примерные
цены (BYN): new_site 900, maps 100, https 60, speed 150, mobile 300, indexing 120, content 400,
schema 120, ai 150, legal 120, conversion 200, security 80, analytics 80, a11y 100, yandex 150.
Тест на реальном примере (белый сайт с HTTPS без редиректа и без разметки → https, schema включены).

## 4. Первое сообщение клиенту (ядро)

Нейросеть (OpenRouter) поверх этих же фактов — `docs/OUTREACH_AI.md`.

`pub fn outreach(...) -> Outreach { lang, short, email_subject, email_body }` — по мини-отчёту,
3–4 главным подтверждённым проблемам простыми словами, профилю менеджера из настроек.
Стиль — как одобрил пользователь (короткий, вежливый, по делу, тире-список, без markdown):

```
Здравствуйте! Я делаю сайты и SEO для клиник. На belodent.by нашлось несколько проблем, из-за которых вы теряете пациентов:

— браузер пишет «Не защищено»: сертификат у вас есть, но нет перенаправления на https
— главная весит около 15 МБ, с мобильного интернета грузится долго
— нет карты сайта и разметки для поисковиков, поэтому вас хуже находят по запросам вроде «стоматолог Минск»

Подробный разбор прикрепляю. Могу всё исправить и провести SEO-оптимизацию. Если интересно, пришлю план и стоимость.

Почта для связи: hello@example.com
```

— «для клиник / салонов / ресторанов / бизнеса» и «пациентов / клиентов / гостей» — по категории;
— сайта нет (none/social/stub/dead) — другой текст: «у вас нет сайта / вместо сайта …, клиенты
с карт уходят к конкурентам; могу сделать сайт…»;
— язык: русский для by/ru/kz/ua/uz/kg и русскоязычных городов, иначе английский;
— письмо — с темой («Сайт belodent.by — что мешает пациентам вас найти») и подписью
(имя, почта, телефон/Telegram — что заполнено). Без гендерных глаголов прошедшего времени
от первого лица («нашёл/нашла» → «нашлось»). Текст по проблеме — без технических слов.

## 5. Сервер (API)

- `GET /api/businesses/{id}` — как сейчас + `contacts`, `activities`, `proposal` (собранный), `outreach`.
- `PATCH /api/businesses/{id}` — плюс `deal_price`, `deal_currency`, `next_action_at`, `next_action`,
  `contact_person`, `extra_contacts`, `proposal`. Смена статуса или цены — запись в `activities`.
- `POST /api/businesses/{id}/activities` `{kind, channel?, text?, at?}`; `DELETE /api/activities/{aid}`.
- `POST /api/businesses/{id}/sent` `{channel, text?}` — «отправили первое сообщение»: activity
  `message`, статус `new` → `contacted`, `next_action_at` (если пусто) = сегодня + 3 дня,
  `next_action` = «Проверить ответ».
- `GET /api/leads` — плюс `deal_price`, `deal_currency`, `next_action_at`, `next_action`,
  `contact_person`, `last_activity_at`; в лиды попадают и компании с ценой или следующим шагом.
- `GET /api/leads.csv` — то же в CSV (UTF-8 с BOM, `;`), для Excel.
- `GET /api/businesses/{id}/proposal.pdf` — PDF страницы `/proposal/{id}` через `render::print_pdf`
  (как `report.pdf`), имя файла «КП <host или название>.pdf».
- Настройки (`settings.rs`, `/api/settings`): `manager_name`, `manager_email`,
  `manager_phone`, `manager_telegram`, `company_name`, `intro` (своя первая
  фраза, пусто — по категории), `currency` (по умолчанию `BYN`), `price_list` (JSON-массив
  `{id, title, price, enabled}` — правки к пакетам).

## 6. Интерфейс (web)

- **Страница компании**: блок «Работа с клиентом» вместо нынешнего WorkCard —
  статус-воронка (чипы), следующий шаг (дата + текст, просроченный — красным), цена сделки,
  контактное лицо, заметки; **контакты** — список с кнопками «скопировать» и ссылками
  (позвонить, написать в WhatsApp/Telegram/Viber, открыть Instagram, mailto), поле «добавить контакт»;
  **первое сообщение** — вкладки «Мессенджер» и «Письмо», текст можно править, «Скопировать»,
  «Отметить как отправленное» (без гендерного глагола), канал;
  **журнал** — лента касаний (дата, канал, текст), быстрые кнопки «написали / ответили / звонок /
  встреча / отправили КП / заметка»; **план работ и КП** — пакеты с галочками, ценами (можно править),
  пунктами «что сделаем», доп. строка, скидка, итог → «Сохранить», «Открыть КП», «Скачать КП (PDF)»,
  «Скачать отчёт (PDF)».
- **Страница `/proposal/:id`** — печатная (A4, как `/report/:id`): шапка с названием компании и
  сайтом, «что сейчас» (балл, 3–5 главных проблем простыми словами), план работ по пакетам с
  пунктами и ценами, итог, срок действия, контакты менеджера из настроек. Без технического жаргона.
- **Лиды**: воронка — чипы статусов со счётчиками и суммой сделок; фильтр «Сегодня и просрочено»;
  колонки: компания, статус, следующий шаг (дата, просрочено — красным), цена, контакт, последнее
  касание, балл; «Скачать CSV».
- **Настройки**: раздел «Профиль и подпись» (имя, почта, телефон, Telegram, компания, первая фраза,
  валюта) и «Прайс» (таблица пакетов: название, цена, вкл/выкл).
- **Отчёт для клиента** (`/report/:id`): заголовки пунктов уже простыми словами (`meta.labels`);
  строки «Сейчас: …» с техническими деталями (имена файлов, коды) — под спойлером «подробности для
  разработчика» или мелким шрифтом в конце; раздел «Что уже в порядке» — тоже простыми словами
  (нужны формулировки «в норме» — где их нет, прятать в «подробности»).
