# Письма нейросетью (OpenRouter) — устройство и план (25.11.2026)

Продолжение `docs/SALES.md` §4 (шаблонное первое сообщение). Цель — чтобы первое письмо и сообщение клиенту
составляла любая модель из каталога OpenRouter, а менеджер мог править всё, что уходит в модель: модель,
инструкцию, запросы, рассуждение, параметры. Дальше — автоматическая отправка и контроль ответов (этапы 2–3).

## Этап 1 — сделано

### Ядро `crates/core/src/llm.rs`
- `AiProfile` — профиль нейросети: `model`, `fallback_models`, `system` (инструкция), `email_prompt`,
  `short_prompt`, `temperature`, `top_p`, `top_k`, `min_p`, `top_a`, штрафы, `seed`, `max_tokens`, `stop`,
  `verbosity`, `json_mode` (auto/on/off), `reasoning` {`mode`: default/off/effort/budget, `effort`,
  `max_tokens`, `exclude`}, `provider` {order, only, ignore, allow_fallbacks, data_collection, zdr, sort,
  require_parameters}, `extra` — любой JSON, накладывается на запрос последним (`null` убирает поле).
- Факты — те же, что у шаблонного письма: `sales::letter_facts` (главные подтверждённые проблемы простыми
  словами, предложение, первая фраза, город на языке письма, подпись, шаблонные тексты как образец).
  Переменные шаблонов — `VARS` (`{{company}}`, `{{problems}}`, `{{signature}}`…), пустые значения
  подставляются словами («нет», «не указано»).
- `build_request` — тело запроса к `/chat/completions`; незаданные параметры не отправляются;
  `json_mode: auto` берёт структурированный ответ (json_schema), если модель умеет, иначе json_object.
- `parse_letter` — JSON `{subject, body}` (и в ```json```), иначе текст с «Тема: …».
- `lint_letter` — замечания по правилам стиля: нет темы, markdown, «[Ваше имя]», `{{…}}`, глаголы с родом
  от первого лица, упоминание нейросети, не тот язык, длина, нет почты из подписи.
- `explain_error` — ошибки OpenRouter по-русски (401 ключ, 402 кредиты, 404 модель/политика данных, 429 лимит…).

### Сервер `crates/server/src/ai.rs`
- `GET /api/ai/meta` (переменные, профиль по умолчанию), `GET /api/ai/models` (каталог, кэш 1 ч),
  `GET /api/ai/key` (остаток кредитов, бесплатные запросы на сегодня).
- `POST /api/businesses/{id}/ai/preview` `{kind, profile_id? | profile?}` — точный запрос без отправки.
- `POST /api/businesses/{id}/drafts` — составить и сохранить черновик; `GET` — список;
  `PATCH/DELETE /api/messages/{mid}`. `POST /businesses/{id}/sent` принимает `message_id`, `subject`, `body`:
  черновик помечается отправленным с итоговым текстом, исходник модели остаётся в `ai.original`.
- `POST /api/ai/batch` `{ids, kind, profile_id?, skip_existing}` — массово в фоне (параллельность
  `ai_concurrency`, повтор при 429/5xx до 3 раз), `GET /api/ai/batch`, `POST /api/ai/batch/cancel`.
  Ключ, кредиты, неверный запрос, нет модели, лимит — партия останавливается с причиной.
- Таблица `messages` (id, business_id, created_at, updated_at, direction out/in, kind email/short,
  status draft/sent, subject, body, ai JSON, sent_at). `ai`: профиль, модель (фактическая), провайдер,
  запрос, ответ как есть, ход рассуждения, токены, цена, время, замечания проверки, исходный текст.
- Настройки: `openrouter_key` (секрет, маска), `ai_profiles`, `ai_profile` (основной), `ai_concurrency`.
- OpenRouter — обычным маршрутом системы (через VPN, если включён), не через «напрямую мимо VPN».
- Проверки: `cargo test -p scanner-core llm`, `cargo test -p scanner-server drafts_preview_sent_and_batch`
  (поддельный OpenRouter на локальном порту; для ручных проверок адрес подменяет `MAPS_SCANNER_OPENROUTER_URL`).

### Интерфейс
- Настройки → «Нейросеть для писем»: ключ и его проверка, профили (новый, копия, основной, удалить),
  каталог моделей с поиском, ценой, «только бесплатные», рассуждение по возможностям модели, все параметры
  (неподдерживаемые моделью помечены), провайдеры, свой JSON, переменные, проба на компании до сохранения.
- Страница компании → «Первое сообщение»: «Составить письмо/сообщение», выбор профиля, «Запрос к модели»,
  черновики с моделью, временем, ценой, замечаниями, ходом рассуждения, запросом и ответом.
- Страница скана → «Письма нейросетью (N)» по отфильтрованному списку, ход, цена, остановка, ошибки.

## Промпт по умолчанию (25.11, переделан по просьбе пользователя)

Тон — спокойный, «живой человек, который делает сайты»: без громких званий (SEO-специалист, эксперт),
рекламных слов и восклицаний; 2–3 абзаца связного текста без списков и тире; одна-две самые заметные проблемы;
мягкое предложение без цены. Шаблонное письмо больше не передаётся как образец. Новые переменные:
`{{portfolio}}` и `{{about_me}}` (Настройки → Профиль: «Портфолио», «О себе — для нейросети»),
`{{attachment}}` (будет ли PDF-разбор). Портфолио попадает и в подпись шаблонного письма («Примеры работ: …»).
Проверка текста дополнительно отмечает громкие слова («эксперт», «под ключ», «гарантируем», «в топ») и глаголы
прошедшего времени от первого лица в любом месте текста («заметил», «заглянул», «приложил»…). Проверено на
deepseek/deepseek-v4-flash (25.11): тон спокойный, но «Заглянул/Зашёл» модель пишет даже при явном запрете —
поэтому в профиле `fix_lint` (по умолчанию включено): при замечаниях модели уходит второй запрос «исправь только
это» (`llm::build_fix_request`); первый вариант сохраняется в `ai.first`, цена — за оба запроса (≈ $0.0002–0.0003
за письмо у DeepSeek V4 Flash).

## Этап 2 — рассылка по почте (сделано 25.11)

- **Сервер `crates/server/src/mail.rs`** (SMTP через `lettre` на rustls/ring): одна фоновая задача на сервер.
  Письма уходят по одному: случайная пауза `mail_interval_min..max`, дневной лимит `mail_daily_limit`,
  окно `mail_window_start..end` по местному времени (конец ≤ начала — круглые сутки), «только по будням».
  Флаг `mail_running` в настройках — рассылка переживает перезапуск; включается только кнопкой.
- **Очередь** — та же таблица `messages`: `draft → queued → sending → sent / failed`, колонки `to_addr`, `queued_at`,
  `message_id` (`<…@домен-отправителя>`, для будущих ответов), `error`. После перезапуска `sending` → `failed`
  с просьбой проверить «Отправленные» (неизвестно, ушло ли).
- **Что и кому решает менеджер**: в скане — галочки у компаний (или все показанные) → «В рассылку»: текст —
  черновик нейросети, шаблон или «черновик, иначе шаблон»; пропуск без почты, без проверки, уже отправленных,
  уже в очереди и (по желанию) тех, с кем уже работаете. Адрес — первая почта компании не для вакансий.
  На странице компании → вкладка «Письмо» → «В рассылку» (адрес выбирается). Массовая генерация нейросетью
  умеет «сразу в очередь». Страница «Рассылка»: пуск/пауза, чего ждём и когда следующее, очередь (правка адреса,
  темы и текста, «убрать в черновики»), «не ушли» (повторить), «отправлено».
- **После отправки** (`api::record_sent`, то же, что «Отметить как отправленное»): касание `message` (email) с
  текстом письма, «Новый» → «Написали», шаг «Проверить ответ» через 3 дня.
- **Письмо**: обычный текст, строка отказа в конце (`mail_footer` / `mail_footer_en` по языку письма),
  `List-Unsubscribe: <mailto:…?subject=unsubscribe>`, Reply-To по желанию, PDF-разбор сайта вложением
  (`mail_attach_report`, не для компаний без сайта; нужен Chromium).
- **Сбои**: отказ адресата (5xx) — письмо в «не ушли», рассылка дальше; 3 отказа подряд — пауза; 4xx — повтор через
  20 мин; неверный логин (535 и т. п.), нет связи, TLS, PDF не собрался — пауза с причиной, письмо остаётся в очереди.
- **Проверки**: `cargo test -p scanner-server mail` — поддельный SMTP на локальном порту (режим `plain` разрешён
  только для localhost): пробное письмо, очередь с пропусками, отправка, смена статуса и журнала, отказ 550,
  пауза, недоступный сервер. Вживую проверено на копии базы с поддельным SMTP: письма, вложение PDF, статусы.

### Рабочее время, вход через аккаунт, без спама (25.11, вечер)

- **Рабочее время получателя.** Окно `mail_window_start..end` считается по местному времени получателя:
  часовой пояс — `region::time_zone(страна скана, координаты компании)` (страны с несколькими поясами — по
  долготе и широте; страна неизвестна — пояс по долготе; нет координат — ваш). Только по будням и только днём:
  окно в пределах 6–22, «круглые сутки» и выходные убраны (старое значение в базе → 9–18). Рассылка берёт
  первое письмо очереди, у получателя которого сейчас рабочее время; иначе ждёт ближайшего («ждёт рабочего
  времени получателей»). Дневной лимит — по вашему дню (это репутация вашего ящика). Часовые пояса — `jiff`
  с системной базой `/usr/share/zoneinfo`.
- **Без спама (`MailGuard`).** Проверяется при постановке в очередь (скан, страница компании, «сразу в
  рассылку» у нейросети) и ещё раз прямо перед отправкой. Не пишем: (1) повторно — одно письмо на компанию,
  на сайт (регистрируемый домен; поддомен конструктора и сайт в региональной зоне вроде `*.minsk.by` —
  целиком), на адрес и на домен адреса (кроме бесплатной почты) — по всем сканам, включая отмеченные вручную
  «отправлено»; перед отправкой мешают только ушедшие письма, иначе два письма одному сайту не пустили бы друг
  друга; (2) сетям — состояние «точка сети» и один проверенный сайт у 5+ разных точек (клетка ≈ 100 м) во всех
  сканах; (3) госорганизациям — `scanner_core::public_sector`: госдомен сайта или адреса письма (`.gov`, `gov.by`,
  `gov.uk`, `gouv.fr`, `minsk.edu.by`, `nhs.uk`, `mos.ru`, местные домены США…), OSM `operator:type`, форма
  в названии («УЗ», «ГУО», «ГБУЗ», «МБОУ», «КУП», «РУП»…), слова («исполком», «городская поликлиника»,
  «детский сад № 5», «city council», «Finanzamt», «mairie»…), кроме названий с частной формой; (4) закрытым.
  Проверяется только адрес письма, не все контакты: белорусские магазины обязаны указывать почту исполкома
  для жалоб — по ней магазин не госорганизация, а для письма выбирается его собственный адрес. Прогон по копии
  базы (15 267 проверенных компаний): из имеющих почту отсеяно 288 точек сетей, 1 сеть по нескольким сканам,
  ~185 повторов сайта или адреса, ~55 госорганизаций; ложные «гос» (поддомен `edu.` у частного сайта, почта
  исполкома у магазинов) исправлены. Пропуск перед отправкой — в «не ушли» с причиной, без паузы рассылки.
- **Вход через аккаунт (`crates/server/src/oauth.rs`).** Google, Яндекс, Microsoft: OAuth 2.0 с PKCE, адрес
  возврата `http://127.0.0.1:<порт>/api/mail/oauth/callback`, SMTP с XOAUTH2 (`lettre` `Mechanism::Xoauth2`).
  Приложение OAuth регистрирует владелец ящика (Client ID и секрет — в настройках; Google — тип «Desktop app»,
  опубликовать «In production», иначе вход живёт 7 дней). Токены — в настройках, наружу не отдаются; короткий
  обновляется по долгому перед отправкой (у Яндекса и Microsoft приходит новый долгий — сохраняется); почта не
  приняла токен — он сбрасывается, рассылка на паузе с причиной. «Выйти» отзывает доступ у Google и Яндекса.
  Mail.ru вход через аккаунт сторонним программам не даёт — только пароль приложения. Проверки:
  `cargo test -p scanner-server oauth` (поддельный сервис OAuth и SMTP: вход, XOAUTH2, обновление, отзыв);
  для ручных проверок адрес сервиса подменяет `MAPS_SCANNER_OAUTH_URL`. С настоящими Google/Яндекс/Microsoft
  не проверено (нужно зарегистрированное приложение).

Право — решать менеджеру до запуска: реклама по почте без согласия запрещена в России (38-ФЗ) и ограничена в
Беларуси и ЕС (ePrivacy/GDPR); в Великобритании (PECR) и США (CAN-SPAM) компаниям писать можно с возможностью
отказа. Мессенджеры автоматизировать законно нельзя — только копирование.

## Этап 3 — контроль ответов (план)

1. IMAP того же ящика (IDLE или опрос раз в 1–5 мин): ответы связываются с письмом по `In-Reply-To` /
   `References`, иначе по адресу; сохраняются в `messages` с `direction = 'in'`.
2. Разбор ответа моделью (решает модель, без правил на регулярках): интерес / вопрос / отказ / автоответ /
   недоставка. Итог — статус лида, следующий шаг, запись в журнал, уведомление; отказ — в список «не писать».
3. ~~Повторные письма~~ — не делаем: правило «одно письмо на сайт» (решение пользователя 25.11). Ответ «нет» —
   статус «Отказ» и в список «не писать».
4. Черновик ответа клиенту нейросетью по переписке — менеджер правит и отправляет.
5. Сводка: отправлено, доставлено, ответили, интерес, отказ — по сканам и профилям (сравнение профилей).
