# Сканер карт (maps-seo-scanner)

Локальное приложение: ищет компании на картах в заданном районе, проверяет их сайты
по каталогу из 214 метрик (SEO, готовность к ИИ-поиску, лендинг, факторы Яндекса) и сортирует
лидов: **горячие** — сайта нет, он не работает или вместо него соцсеть; **тёплые** — сайт слабый,
с критичными ошибками или есть, но не указан в карточке; **холодные** — сайт в порядке или это
точка сети. Работает в любой стране: язык запросов, формат адресов, телефоны и правовые проверки
зависят от страны скана.

- Один файл `maps-seo-scanner`: сервер и встроенный веб-интерфейс (http://127.0.0.1:8787),
  база — SQLite в домашнем каталоге. Ничего, кроме него, ставить не обязательно.
- Без ключей работает на открытых данных — OpenStreetMap и Overture Maps. Ключи Google,
  Яндекса и PageSpeed добавляют рейтинги, отзывы и Core Web Vitals.
- Интерфейс и отчёты — на русском.
- Backend — Rust (tokio, axum, reqwest, scraper, SQLite), интерфейс — React + TypeScript + Vite,
  карта на Leaflet.

## Установка

Готовые сборки — на странице [Releases](https://github.com/GrayNexTry/site_scanner/releases):
Linux **x86_64** и **aarch64** (ARM). Подходит любой дистрибутив с glibc 2.28 и новее: Ubuntu
20.04+, Debian 10+, Linux Mint, Fedora, Arch, openSUSE, RHEL/Alma/Rocky 8+. На Alpine (musl) —
только сборка из исходников.

```sh
curl -LO https://github.com/GrayNexTry/site_scanner/releases/latest/download/maps-seo-scanner-linux-x86_64.tar.gz
tar -xzf maps-seo-scanner-linux-x86_64.tar.gz
cd maps-seo-scanner-linux-x86_64
./install.sh
maps-seo-scanner --open
```

На ARM (Raspberry Pi 4/5, ARM-серверы) замените `x86_64` на `aarch64`. Проверить архив:
скачайте рядом `….tar.gz.sha256` и выполните `sha256sum -c maps-seo-scanner-linux-x86_64.tar.gz.sha256`.

`install.sh` ставит всё в домашний каталог, root не нужен:

- `~/.local/bin/maps-seo-scanner` — сама программа;
- ярлыки в меню приложений (GNOME, KDE, Xfce и др.): **«Сканер карт»** запускает сервер в фоне
  (временная служба `systemd --user`, лог — `journalctl --user -u maps-seo-scanner`) и открывает
  интерфейс в браузере, если сервер уже работает — просто открывает; **«Сканер карт: остановить
  сервер»** — останавливает. Из консоли то же самое: `maps-seo-scanner-launch start|stop|status`.

`./install.sh --no-desktop` — без ярлыков, `./install.sh --uninstall` — удалить (база сканов
остаётся). Если `~/.local/bin` нет в `PATH`, установщик подскажет, что добавить в `~/.bashrc`.
Можно и вовсе не устанавливать: `./maps-seo-scanner --open` прямо из распакованного каталога.

### Что ещё пригодится (необязательно)

- **Chromium или Google Chrome** — для сайтов на React, Vue, Angular, у которых текст появляется
  только после выполнения скриптов. Ubuntu/Debian: `sudo apt install chromium` (на Ubuntu —
  snap-пакет), Fedora: `sudo dnf install chromium`, Arch: `sudo pacman -S chromium`. Без браузера
  у таких сайтов метрики, зависящие от текста, помечаются «не измерено», остальное работает.
  Браузер ищется в `PATH` (chromium, google-chrome…) и в `~/.cache/ms-playwright`; путь можно
  задать в настройках.
- **Ключи API** — раздел [«Ключи API»](#ключи-api-настройки). Без них работают OSM и Overture.

## Запуск

```sh
maps-seo-scanner --open                    # сервер на http://127.0.0.1:8787 и браузер
maps-seo-scanner --listen 127.0.0.1:9000   # другой порт
maps-seo-scanner --data-dir ~/scans        # другой каталог для базы
maps-seo-scanner --help
```

Сервер слушает только localhost: в настройках хранятся ключи API. Остановить — Ctrl+C (или ярлык
«остановить сервер», если запускали ярлыком). База — `~/.local/share/maps-seo-scanner/scanner.db`
(права 0600).

Первый скан: **Новый скан** → точка на карте и радиус → категория (стоматология, автосервис,
салон… или «Все организации») → источники → запуск. Сканер найдёт места, поищет сайты тем, у кого
их нет в карточке, проверит сайты и разложит лидов по классам. Скан можно остановить на любом
этапе кнопкой **«Остановить»** — в списке сканов или на странице скана.

## Проверка одного сайта из консоли

Для разработки сайтов (в том числе ИИ-агентами): те же метрики, что в отчёте, без сервера и базы.

```sh
maps-seo-scanner audit http://localhost:4321/ --country ru --city Москва --service стоматология \
  --name "Клиника" --phone "+7 495 123-45-67" --address "Москва, Тверская, 1" --hours "Mo-Fr 09:00-21:00"
```

Выводит критичные провалы и «внимание» с нормами, сжатый список «не измерено» и (для localhost)
то, что проверяется только после выкладки на домен: TLS, редиректы, HSTS, DNS почты. `--json` —
для разбора, `--all` — показать и пройденные. Код выхода: 0 — критичных нет, 1 — есть,
2 — сайт не открылся. Ключи PSI и Safe Browsing, браузер и прокси берутся из настроек сканера.
Все ключи — `maps-seo-scanner audit --help`.

## Сборка из исходников

Нужны git, [Rust](https://rustup.rs) stable (edition 2024), Node.js 22 или новее с npm и
компилятор C (gcc или clang — для SQLite, ring и zstd).

| Система | Пакеты |
|---|---|
| Ubuntu / Debian | `sudo apt install git build-essential` + Node.js 22+ с [nodejs.org](https://nodejs.org) или через nvm (в репозиториях часто старый) |
| Fedora | `sudo dnf install git gcc nodejs npm` |
| Arch | `sudo pacman -S git base-devel nodejs npm` |

```sh
git clone https://github.com/GrayNexTry/site_scanner.git
cd site_scanner
scripts/build.sh                           # интерфейс + релизный бинарник
./target/release/maps-seo-scanner --open
```

`scripts/install.sh` — собрать и положить бинарник в `~/.local/bin`;
`scripts/install.sh --desktop` — ярлыки в меню, запускающие сборку из `target/release`;
`scripts/install.sh --remove-desktop` — убрать ярлыки.

Бинарник из `scripts/build.sh` привязан к версии glibc вашей системы. Переносимые архивы, как в
релизах (glibc ≥ 2.28, x86_64 и aarch64), собирает `scripts/dist.sh` через
[cargo-zigbuild](https://github.com/rust-cross/cargo-zigbuild):

```sh
pip install ziglang cargo-zigbuild   # лучше в venv
scripts/dist.sh                      # → dist/maps-seo-scanner-linux-{x86_64,aarch64}.tar.gz
```

**Выпуск релиза:** поднять `version` в `Cargo.toml`, закоммитить и отправить тег
`git tag v0.2.0 && git push origin v0.2.0` — GitHub Actions (`.github/workflows/release.yml`)
соберёт архивы и опубликует релиз. Тег должен совпадать с версией в `Cargo.toml`.

## Разработка

```sh
scripts/dev.sh        # cargo run (API на :8787) + vite (интерфейс на :5173 с прокси /api)
cargo test --workspace
cd web && npm run typecheck
python -I scripts/sanity_check.py [scan_id]   # противоречия в выдаче скана
```

Каталог метрик — `docs/METRICS.md`; после правки пересоздать `metrics.yaml/json`:
`python -I scripts/gen_metrics_yaml.py` (нужен PyYAML: `pip install pyyaml`), затем
`cargo test --workspace`.

`scripts/sanity_check.py` ищет в проверенном скане признаки ошибок самих проверок: «заглушка» при
большом тексте, «не работает» при ответе 200, горячий лид при хорошем сайте, мусорные предположения
о сайте, общий сайт у многих компаний без пометки «сеть», частые стоп-факторы, метрики с провалом у
большинства сайтов. Порядок работы: поправить проверку → «Перепроверить всё» (или «Пересчитать
оценки», если менялась только логика оценки) → запустить снова; список должен сокращаться.

```
  region.rs             страна скана: юрисдикция (РФ, ЕС, UK, США), язык, домены, порядок адреса
  lexicon.rs            многоязычные словари и шаблоны (ru, en, de, fr, es, it, nl, pl, pt)
  discover.rs           поиск сайта в обход карт и проверка кандидатов
  search.rs             веб-поиск: Brave API, Yandex Search API, без ключа — DuckDuckGo/Bing
  render.rs             рендер сайтов на скриптах в headless Chromium (--dump-dom)
  http.rs               клиент: ручные редиректы с цепочкой, TTFB, лимит тела, windows-1251

  page.rs               разбор HTML в плоскую структуру
  checks/               проверки по категориям A–R (R — факторы Яндекса): чистые функции → результат по каждой метрике
  scoring.rs            балл категорий и общий, стоп-факторы, класс лида и приоритет
crates/server/          axum: /api, фоновые сканы, события SSE, встроенный интерфейс, команда audit
web/                    React-интерфейс
docs/METRICS.md         каталог метрик — источник правды; metrics.yaml/json генерирует
                        scripts/gen_metrics_yaml.py
docs/site-build/        чеклист и шаблоны сайта под все метрики (для скилла client-site-build)
packaging/              установщик архива релиза, лаунчер и ярлыки меню приложений
skills/                 скилл client-site-build для Claude Code
```

Скан: страна и названия города по точке (Nominatim) → поиск мест у выбранных источников →
слияние дублей (телефон, домен, название рядом) → для компаний без своего сайта — поиск сайта
в обход карт → параллельный аудит сайтов (по умолчанию 8 сайтов, 4 запроса на сайт) → балл и
класс лида. Прогресс приходит в интерфейс событиями.

## Полный поиск по району и мини-отчёт

Категория «Все организации» берёт из OSM любые магазины, мастерские, медицину, коммерческие
офисы, кафе, салоны, фитнес, гостиницы и т. п., а из Overture — всё, кроме парков, памятников,
госучреждений, храмов и транспорта. Лимит — до 20 000 мест, при превышении берутся ближайшие к
центру. Для сравнения: в круге 5 км от центра Минска в OSM 11 тысяч организаций (у 4,6 тысячи
указан сайт), в круге 1,5 км Overture даёт ещё 2,3 тысячи мест.

Для больших сканов (больше 300 мест) по умолчанию включена **быстрая проверка**: главная и пара
страниц, без PageSpeed и без угадывания доменов, сайтов одновременно вдвое больше. Точки одной
сети с общим сайтом проверяются один раз; пять и больше точек с одним названием в районе — сеть
(холодный лид). Полная проверка одной компании — кнопка «Перепроверить» в её карточке.

**Мини-отчёт** есть у каждой компании: ситуация с сайтом одной строкой («Сайта нет», «Сайт
kinderdentist.de есть, но не указан в карточке», «Слабый сайт: 31/100, 9 критичных проблем»),
до пяти проблем простыми словами и что предложить; кнопка «Скопировать для письма». Над таблицей
скана — **ситуация с сайтами по району**: сколько без сайта, с соцсетью вместо сайта, с заглушкой,
с нерабочим, со слабым, средним и хорошим сайтом (плитки — фильтры таблицы), и самые частые
проблемы среди проверенных сайтов. В CSV — колонки «Ситуация с сайтом», «Главные проблемы»,
«Что предложить».

## Поиск сайта в обход карт

Если в карточке нет сайта или там соцсеть, сканер ищет сайт сам (Настройки → «Поиск сайтов»):

1. домен почты из карточки (OSM `email`), если это не бесплатная почта;
2. ссылки со страниц Taplink, Linktree, Telegram, VK из карточки (Instagram и Facebook без входа закрыты);
3. официальный сайт бренда в Wikidata — для точек сетей (такие лиды уходят в холодные);
4. домены по названию: транслитерация, варианты без общих слов («Стоматология Улыбка» → ulybka.ru,
   ulybka-dent.ru, улыбка.рф), зоны страны; существование проверяется через DNS-over-HTTPS;
5. веб-поиск «"Название" город»: Brave Search API или Yandex Search API по ключу; без ключа —
   HTML-выдача DuckDuckGo и Bing (против их правил, через VPN почти всегда капча — тогда поисковик
   отключается до перезапуска).

Кандидат открывается (главная и страница контактов). **Подтверждён** — если на сайте есть телефон
(в том числе в коде страницы) или адрес из карточки, либо он пришёл из надёжного источника и совпало
название. Совпали только название и город — это **«возможно, их сайт»**: подтверждает человек кнопкой
«Это их сайт» или вводит адрес вручную. Найденный сайт проверяется как обычный, а лид меняется
с «нет сайта» на «сайт есть, но не указан в карточке».

## Работа с клиентом: от находки до КП

Подробное ТЗ — [docs/SALES.md](docs/SALES.md). На странице компании сверху — всё, что нужно менеджеру:

- **Работа с клиентом** — воронка (новый → написали → переговоры → КП отправлено → клиент / отказ /
  не работаем), следующий шаг (дата и что сделать; просроченный — красным), цена сделки и валюта,
  контактное лицо, заметки.
- **Контакты** — всё, что нашлось: из карточек на картах (телефон, почта, ссылки), с сайта (почты,
  телефоны, Instagram, Telegram, WhatsApp, Viber и др.) и добавленные вручную; у каждого — «скопировать»
  и действие (позвонить, написать). Почты вакансий помечены.
- **Первое сообщение** — готовый текст для мессенджера и письмо с темой: 2–4 главные проблемы простыми
  словами, подпись из «Настройки → Профиль». Язык — по стране компании (русский или английский).
  «Отметить как отправленное» — статус «Написали» и шаг «Проверить ответ» через 3 дня.
- **Нейросеть** — там же «Составить письмо / сообщение»: любая модель OpenRouter пишет по тем же
  подтверждённым фактам. В «Настройки → Нейросеть» правится всё: модель и запасные модели, инструкция,
  запросы для письма и мессенджера, рассуждение (выключить, уровень, бюджет токенов), параметры генерации,
  провайдеры, свои поля запроса. У черновика видны ход рассуждения, точный запрос, цена и замечания по
  стилю. На странице скана — «Письма нейросетью» для всего отфильтрованного списка. Подробно —
  [docs/OUTREACH_AI.md](docs/OUTREACH_AI.md).
- **Рассылка по почте** — в «Настройки → Почта для рассылки» ящик: вход через аккаунт Google, Яндекса или
  Microsoft (OAuth, своё приложение регистрируется один раз — инструкция там же) или пароль приложения
  (Gmail, Яндекс, Mail.ru, любой SMTP); правила: писем в день, пауза между письмами, рабочее время,
  PDF-разбор вложением, строка «как отказаться». Письма уходят только по будням и днём по местному времени
  получателя (часовой пояс — по городу скана). Без спама: одно письмо на сайт и на адрес по всем сканам,
  повторных писем нет, сетям и госорганизациям рассылка не пишет. В скане отмечаете компании галочками →
  «В рассылку» (черновик нейросети или шаблон), на странице «Рассылка» перечитываете и правите письма и
  нажимаете «Запустить». Письма уходят по одному; после отправки компания — «Написали», в журнале — текст
  письма, шаг «Проверить ответ».
- **Журнал** — касания (написали, ответили, звонок, встреча, КП); смена статуса и цены пишется сама.
- **План работ и КП** — пакеты работ из найденных проблем с ценами из «Настройки → Прайс» (свой прайс
  для каждой валюты), можно выключать пакеты, править цены, добавить строки и скидку. «Открыть КП»,
  «Скачать КП (PDF)», «Скачать отчёт (PDF)» — PDF без служебных строк браузера.

«Лиды» — все компании в работе из всех сканов: воронка со счётчиками и суммой сделок, фильтр
«Сегодня и просрочено», «Скачать CSV» для Excel.

«Отчёт для клиента» и «КП» — страницы A4 на языке клиента: оценка, главное, что исправить, разделы с
пояснениями «зачем это»; технические замеры — в приложении «для вашего разработчика» в конце. У сайтов-
заглушек и неработающих — «сайта по факту нет», без баллов.

## Сайты на скриптах

Если в исходном HTML почти нет текста (React, Vue, Angular), главная рендерится в headless Chromium,
и проверки идут по готовой странице; I06 показывает, сколько текста видят ИИ-боты без JS. Где взять
браузер — в разделе [«Что ещё пригодится»](#что-ещё-пригодится-необязательно).

## Свой прокси

Если сайты закрыты для страны вашего выхода (российские сайты через зарубежный VPN), задайте в
настройках свой прокси: `socks5h://127.0.0.1:1080` (например, SSH-туннель `ssh -D 1080 user@vps`),
`http://user:pass@host:3128`. Сайт, который напрямую не открылся или ответил 403/451/429, проверяется
целиком ещё раз через прокси; в карточке это видно, скорость ответа включает задержку прокси.
Режим «всё через прокси» пускает через него и карты, поиск, API. Рендер скриптов идёт через прокси,
только если в адресе нет логина и пароля (Chromium их не принимает из командной строки).
Бесплатные публичные списки прокси не поддерживаются намеренно: это обычно чужие взломанные
устройства, они видят трафик и подменяют страницы — результаты аудита были бы недостоверны.

## Ключи API (Настройки)

Все ключи необязательны.

| Ключ | Зачем | Где взять |
|---|---|---|
| Google Places API (New) | места Google: сайт, рейтинг, отзывы, статус | Google Cloud Console, нужен платёжный аккаунт |
| Яндекс «API Поиска по организациям» | места Яндекса: сайт, телефоны, часы | developer.tech.yandex.ru |
| PageSpeed Insights | Core Web Vitals и Lighthouse (D01–D11, Q01) | Google Cloud Console; без ключа общий лимит исчерпан |
| Safe Browsing | проверка по спискам опасных сайтов Google (B13; список Яндекса проверяется без ключа) | Google Cloud Console |
| Brave Search API | веб-поиск сайтов по названию, любая страна | api-dashboard.search.brave.com |
| Yandex Search API + ID каталога | веб-поиск сайтов по названию, лучший для России | Yandex Cloud, роль `search-api.webSearch.user` |

Без ключей работают OpenStreetMap и Overture Maps: бесплатно, но рейтингов и отзывов там нет,
а данные бывают устаревшими (часть «мёртвых» сайтов — это закрывшиеся компании). Overture —
открытые данные Meta, Microsoft, Amazon, TomTom и др. (лицензия CDLA-Permissive-2.0, при
публикации данных нужна ссылка «Overture Maps Foundation»), выпуск раз в месяц; читается
выборочно из файлов на S3, район — за 5–15 с.

Яндекс «Поиск по организациям» платный: на 24.11.2026 — 195 000 ₽ в год за 1000 запросов в
сутки, бесплатный тестовый тариф — 7 дней по 100 запросов в сутки. Для поиска лидов это дорого;
тестового периода хватит, чтобы сверить покрытие с OSM и Overture на своих районах.

## Что важно знать

- **VPN и «сайт не пустил сканер».** Сайты страны часто не отвечают на зарубежные IP: обрывают
  соединение, молчат, их DNS-серверы отказывают, защита (DDoS-Guard, Qrator, Cloudflare) показывает
  проверку «вы не робот». Скан из другой страны, чем район, помечает такие сайты «проверить без
  VPN», а не «мёртвые»; мёртвым считается только домен, которого нет в DNS. Над таблицей скана —
  предупреждение и кнопка «Перепроверить недоступные»: выключите VPN (или пустите домены страны
  напрямую, или задайте свой прокси в стране района) и нажмите её. Сканер ходит как свежий Chrome
  под Windows с обычными заголовками браузера, не открывает больше одного сайта одной платформы за
  раз, сайты с неполной цепочкой сертификата проверяет всё равно (о сертификате скажет B04).
  Капчи и проверки «вы не робот» сканер не проходит намеренно — это обход защиты сайта.
  Поисковики без ключа (DuckDuckGo, Bing) с IP VPN и дата-центров отвечают капчей.
- **Страна скана** определяется по точке на карте; для ручной проверки сайта — по доменной зоне.
  От неё зависят язык запросов к Google/Яндексу, Accept-Language при загрузке сайтов, порядок адреса
  и правовые проверки M01–M06: РФ — 152-ФЗ, ИНН; ЕС — GDPR, баннер cookie, Impressum/mentions légales/
  P.IVA/KvK…; UK — Companies Act; США — CCPA. В остальных странах правовые проверки справочные.
- **Факторы Яндекса (раздел R).** Для России, Беларуси, Казахстана, Узбекистана и Кыргызстана
  сканер проверяет то, по чему ранжирует Яндекс: связь сайта с Яндекс Бизнесом, городской номер,
  доменную зону, коммерческие факторы (контакты, каналы связи, оплата, гарантии, прайс, соцсети)
  и нарушения из «Рекомендаций Яндекса для сайтов»: переспам, скрытый текст, popunder и чужие
  перенаправления, клоакинг (запрос с UA YandexBot), малополезные страницы. ИКС и знаки сайта
  (C19, R16) берутся с открытой страницы webmaster.yandex.ru/siteinfo, проверка безопасности по
  базе Яндекса (B13) — с yandex.ru/safety; обе без ключей, не чаще 3 запросов в секунду на всё
  приложение. Это страницы для людей, а не API: если Яндекс сменит разметку, метрики станут
  «не измерено». Поведенческие факторы, регион в Вебмастере, фиды и видимость в Алисе AI
  (R02, R17–R19) — только с доступом клиента.
- **Только пассивные проверки:** то, что видит посетитель или поисковый бот. Никакого перебора путей.
- **Apple Карты** не поддерживаются: у Apple нет публичного API поиска организаций с сайтами.
- **Не измеряется пока:** вёрстка в браузере (E02–E04, E06, E07, Q02: ширина экрана, шрифты,
  тап-цели), позиции в выдаче (K), ссылки (L), геосетка позиций в картах (A20) — это этап аудита с
  платными API. Упоминания в ответах ИИ-ассистентов сканер не считает — он проверяет всё, что на них
  влияет (раздел I). Метрики с доступом к кабинетам клиента (GSC, Вебмастер, Метрика) — этап отчёта.
- **Overpass и Nominatim** — общие бесплатные сервисы OSM с правилами честного использования:
  не запускайте десятки сканов подряд. Overpass опрашивается через 4 зеркала сразу, большой район —
  по квадратам. Поиск в OSM ограничен примерно 4 минутами: если Overpass перегружен (вечером и ночью
  бывает часто), скан продолжается с тем, что успело прийти, и помечается «список неполный»; если не
  ответил никто — список собирается через Nominatim (до 40 мест на участок, не чаще запроса в
  секунду). Кнопка «Повторить поиск» в скане позже добавит недостающие компании к найденным,
  статусы и заметки не трогает. Overture от Overpass не зависит и отвечает за секунды.
- Отчёты и интерфейс — на русском; английская версия отчёта для зарубежных клиентов пока не сделана.
